# Винная подборка

[Открыть приложение](https://kirpepa-wine-quality-hw3.streamlit.app/) · [Исходный код на GitHub](https://github.com/kirpepa/hw3-wine-quality)

Опубликовано на Streamlit Community Cloud 7 ноября 2026 года, Python 3.12. Проверены все четыре вкладки, изменение порога и пакетный прогноз CSV.

Демо к ДЗ-3: готовая логистическая регрессия оценивает вероятность экспертной оценки вина не ниже 7. Общий ползунок порога управляет решением для одного вина, тестовой выборки и загруженного CSV. Обучение и подбор порога выполняются в `HW3_MMDA.ipynb`; приложение только загружает сохранённый пайплайн.

## Запуск

Python **3.12** (локальная версия: **3.12.3**). Версии используемых библиотек зафиксированы в `requirements.txt`.

Из корня этого репозитория:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

В Windows вместо `source .venv/bin/activate` используйте `.venv\Scripts\activate`.

Откройте адрес, показанный Streamlit в терминале (обычно `http://localhost:8501`). Пути к файлам вычисляются от `Path(__file__).resolve().parent`, поэтому рабочая директория не влияет на загрузку.

Рядом с `app.py` должны находиться `model.joblib` (весь пайплайн `StandardScaler` + `LogisticRegression`), `config.json` (выбранный на валидации порог), `test.csv` (12 признаков и `target`). Их создаёт ячейка «Сохранение модели» в ноутбуке. При отсутствии файлов приложение показывает сообщение, а не пытается обучить модель.

## Возможности

- **Одно вино:** 11 числовых признаков и переключатель красного/белого вина; диапазоны и медианы из `test.csv`, вероятность и решение.
- **Модельные метрики:** матрица ошибок, precision, recall, F1, ROC- и PR-кривые с точкой текущего порога. PR-AUC рассчитывается как average precision.
- **Пакетное предсказание:** загрузка CSV, проверки обязательных столбцов, числовых значений, пропусков, бесконечностей и `is_red`; таблица и скачивание прогнозов. Пример CSV можно скачать в самой вкладке.
- **Что выучила модель:** отсортированные коэффициенты после масштабирования и наиболее сильные положительные/отрицательные связи.

CSV использует запятую между столбцами и точку как десятичный разделитель. Порядок признаков восстанавливается по модели; дополнительные столбцы игнорируются с уведомлением. `is_red=0` означает белое вино, `is_red=1` — красное. Решение `prediction=1` принимается при `probability >= threshold`.

Повышение порога уменьшает подборку и обычно повышает precision. Снижение повышает recall, но добавляет ошибочные рекомендации. Итоговый порог выбирается на валидации: интерактивные тестовые метрики нужны для объяснения поведения, а не повторного подбора порога.

## Кэширование

`load_model` использует [`st.cache_resource`](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource): модель хранится одним общим объектом, доступным повторным запускам и сессиям. После загрузки модель не изменяется.

Таблица, конфигурация и вероятности используют [`st.cache_data`](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_data): это сериализуемые результаты вычислений, и каждому вызову возвращается собственная копия. В `test_proba(_model, X, model_version)` аргумент `_model` исключён из хеширования, а версия файла модели включена в ключ явно. Время изменения исходных файлов инвалидирует соответствующий кэш при их замене.

Порог не является аргументом `test_proba`. Движение слайдера повторяет сравнение готовых вероятностей с порогом и расчёт метрик, но не вызывает `predict_proba` для неизменной таблицы заново. При изменении признаков одного вина или загруженной таблицы прогноз для новых признаков рассчитывается и кэшируется.

Без декоратора `joblib.load` повторно читает и десериализует модель при каждом перезапуске скрипта, например после движения слайдера. `st.cache_data` для модели создавал бы копии сериализованного объекта, тогда как здесь нужен общий ресурс.

## Streamlit Community Cloud

Для публикации нужен репозиторий в своём GitHub-аккаунте с этой папкой и доступ к Streamlit Community Cloud.

1. Загрузите все файлы папки `wine_app` в свой GitHub-репозиторий. Не загружайте `.venv`.
2. Откройте [Streamlit Community Cloud](https://share.streamlit.io/), нажмите **Create app**, затем **Yup, I have an app**.
3. Укажите свой репозиторий, ветку и путь `homework/hw_3/wine_app/app.py` (либо `app.py`, если содержимое папки находится в корне отдельного репозитория).
4. В **Advanced settings** выберите **Python 3.12**. Зависимости берутся из `requirements.txt` рядом с `app.py`.
5. Запустите деплой и дождитесь успешного открытия приложения. Проверьте изменение порога, вкладки и загрузку CSV, затем добавьте полученный адрес `https://…streamlit.app` в ноутбук.

Порядок публикации описан в [официальной документации Streamlit](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy). Рабочая версия приложения доступна по ссылке в начале README.
